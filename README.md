# Клуб героев — тестовый paywall

Мобильный экран подписки на Nuxt 4 + TypeScript по макету Figma Make.
Платёжная операция тестовая: реальный платёжный SDK и реальные деньги не
используются.

## Локальный запуск

Требуется Node.js `^22.22.3`, `^24.15.0` или `>=26.0.0`.

```powershell
npm install
Copy-Item .env.example .env
npm run dev
```

Откройте <http://localhost:3000>. Чтобы сохранять тестовые покупки, задайте
`DATABASE_URL` в `.env` в корне проекта:

```env
DATABASE_URL="postgresql://..."
```

После изменения `.env` перезапустите dev-сервер. Не добавляйте `.env` в git и не
публикуйте строку подключения: она содержит пароль базы.

## Структура

- Экран paywall, загрузка тарифов, выбор тарифа и состояния покупки:
  `app/pages/index.vue`.
- Mobile-first стили и адаптивная вёрстка: `app/assets/css/main.css`.
- Маршрут тарифов `GET /api/offers`: `server/api/offers.get.ts`.
- Маршрут тестовой покупки `POST /api/purchase` и запись в PostgreSQL:
  `server/api/purchase.post.ts`.
- Список тарифов: `server/utils/offers.ts`.

`POST /api/purchase` принимает JSON с `offerId`, проверяет тариф, получает или
создаёт случайный ID устройства в HTTP-only cookie, затем записывает покупку в
PostgreSQL. После успешной записи клиент показывает подтверждение. Без
настроенного или доступного подключения приложение возвращает ошибку, а не
имитирует успешное сохранение.

## База данных

Выбрана PostgreSQL в Supabase: это управляемая облачная база, которую можно
использовать и локально, и из задеплоенного приложения. При первой покупке
сервер создаёт таблицу `public.amayakids`, если у пользователя БД есть права на
DDL, и добавляет необходимые столбцы, если их ещё нет.

Ожидаемая схема:

| Столбец | Тип | Назначение |
| --- | --- | --- |
| `id` | `bigint generated by default as identity`, primary key | ID записи покупки |
| `offer_id` | `text not null` | ID тарифа (`monthly` или `yearly`) |
| `device_id` | `uuid not null` | Случайный ID устройства из cookie |
| `created_at` | `timestamptz not null default now()` | Дата и время покупки |

При необходимости таблицу можно создать вручную в Supabase SQL Editor:

```sql
create table if not exists public.amayakids (
  id bigint generated by default as identity primary key,
  offer_id text not null,
  device_id uuid not null,
  created_at timestamptz not null default now()
);
```

В Supabase скопируйте строку подключения в **Connect → Transaction pooler** и
задайте её как `DATABASE_URL`. Для pooler используйте точные host, port и
username из панели Supabase. При ошибке `password authentication failed`
проверьте pooler username и пароль базы; если пароль содержит специальные
символы, URL-кодируйте их. Саму строку подключения не отправляйте в чат.

## Деплой

Рекомендуемая платформа приложения — Vercel: Nuxt поддерживает server-side
рендеринг и серверные API-маршруты. Для постоянного хранилища используется
Supabase PostgreSQL. Деплой ещё не выполнялся. Перед публикацией добавьте
`DATABASE_URL` в серверные environment variables Vercel; не встраивайте его во
frontend. Подключение к Supabase должно быть доступно с выбранного хостинга.

## Проверки и инструменты

При разработке использовался AI-ассистент Copilot SDK в VS Code и просмотр
Figma Make в браузере. Самостоятельно проверены:

- `npm run typecheck` и production-сборка `npm run build`;
- SSR-страница и `GET /api/offers`;
- отклонение неизвестного тарифа через `POST /api/purchase`;
- loading/error UI и отсутствие горизонтальной прокрутки на мобильной ширине.

Успешную запись в Supabase пока подтвердить не удалось: проверка текущего
подключения вернула `password authentication failed`. До исправления учётных
данных успешную запись следует считать непроверенной.

## Следующие шаги

Если бы на задачу было ещё два часа:

1. Исправить учётные данные Supabase и проверить, что покупка действительно
   появляется в таблице.
2. Задеплоить приложение на Vercel, настроить `DATABASE_URL` и проверить
   production-покупку.
3. Добавить автоматические тесты API и интерфейса, затем проверить
   доступность, политику доступа к данным и production-конфигурацию.
